# Study C: generation-budget sensitivity

Status: prospective follow-up after Study B. Freeze before scored runs. Study
B's first-token interface may underuse generative reasoning, so its negative
finding must not be generalized to an unrestricted agent.

Frozen dataset: `experiments/study_c/data/environments-v1.json`, generated with
NumPy 2.2.4 using `make_environment(seed)` for seeds 5000–5023. SHA-256:
`1b30fb9836729e2775b6db993785cc6de7a90ce9a0cb3c6133d762a2606c6bb7`.
Inference reads these bytes rather than regenerating the formal environments.

## Fixed design

- Models: the pinned Qwen2.5-0.5B-Instruct and 7B-Instruct checkpoints. These
  endpoints bracket Study B; no model is selected by a new validation sweep.
- Environments: 24 untouched seeds 5000–5023, generated by Study B's frozen
  command-language generator. Same 16 feedback, 16 direct-test, and 32
  composition-test queries per environment. Freeze the environment JSON/hash
  before inference. Tasks remain synthetic and addition remains commutative.
- Conditions: no examples, 16 true examples, 16 sequential self-generated
  examples, and oracle offsets. No corruption or LoRA in this interface test.
- Interfaces: (a) exactly Study B's first-token scoring; (b) brief reasoning
  followed by a final answer, greedy full generation capped at 128 new tokens.
  No sampling, extra retry, or external evaluator is available at test time.
  Retain the checkpoint's generation defaults, including repetition penalty
  1.1; archive those defaults and the two overrides (`do_sample=False`,
  `max_new_tokens=128`). This is not unpenalized tokenwise argmax.
- Reasoning prompts replace both single-digit-only instructions with:
  `Reason briefly about the state changes. Finish with a line exactly
  "Answer: N", where N is a digit from 0 to 7.` The environment description,
  examples, offsets, and queried problem are otherwise unchanged.
- The parser accepts only a final nonempty line matching `Answer: [0-7]`,
  case-insensitively with optional whitespace. Other output is invalid and
  scored wrong. Record the full text, parsed digit, invalid-format rate,
  generated token count, EOS termination, and maximum-token truncation rate.
  Save generated token IDs through the first EOS so special-token removal
  during text decoding remains auditable.
  Parse text decoded with `skip_special_tokens=True`: all tokenizer special
  tokens are removed. Thus validity concerns rendered text, not raw token
  grammar; an intervening non-EOS special token alone does not invalidate it.
  No second semantic judge repairs a response.
- The self condition solves each feedback query in order using only preceding
  model answers. Store the parsed digit; an invalid response is stored as the
  explicit string `invalid`. This formatting consequence must be reported.
  First-token self history uses the constrained digit, as in Study B.
- Online acquisition and offline provision of the same final examples remain
  equivalent in this passive environment. No active-learning claim is made.

## Primary and secondary endpoints

Primary: for 0.5B composition accuracy, compute the paired environment-level
interaction `(clean - none)_generation - (clean - none)_first_token`.
Report a 95% paired t interval and a 10,000-resample environment bootstrap
interval using RNG seed 819. This tests sensitivity of the feedback effect to
the interface; it does not estimate a pure reasoning-compute effect because
instructions and answer parsing also differ.

Secondary: all model/interface/condition means; clean-minus-self, clean-minus-
none, direct/composition differences, invalid outputs, and truncation. Report
descriptive intervals only. Evaluate the entire fixed grid once, without
optional stopping or changing the token cap after seeing held-out performance.
If truncation is material, report the limit and register a separate follow-up.

## Resources and controls

Batch size 16, bfloat16, SDPA, same tokenizer/chat template, local models only.
Record exact revisions, task/runner hashes, prompt hashes, all raw outputs,
input/output tokens, forward/generation wall times, and peak GPU allocation.
Generated sequences count through EOS (including EOS), excluding later padding.
Run models sequentially. Use `/tmp` on lens for outputs because the main
filesystem filled after Study B; copy completed outputs back to the repository.
Before formal collection, test parsing, prompt consistency, and a development
environment below seed 100. Do not tune prompts to formal seeds.

## Interpretation

A positive interaction alone does not establish a recovered feedback benefit:
it can arise while feedback remains harmful or because the no-feedback control
degrades. Interpret it together with generation's own clean-minus-none contrast
and all four component means. Only evidence of a positive feedback effect under
generation supports recovery under that interface. A null result applies to this prompt,
task family, and 128-token budget. Neither outcome resolves whether a small
agent can develop broad intelligence through long-term interactive learning.
