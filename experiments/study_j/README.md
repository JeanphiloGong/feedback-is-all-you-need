# Study J: full versus local program context

The [prospective protocol](../../notes/protocol-v10-local-context-prior.md)
compares the same 1,172-parameter GRU with full-prefix and last-two-token
prediction. Both start from identical tensors and learn from the same accepted
programs with the same update schedule. The intervention supplies a context
restriction; it changes recurrent state, gradient paths, and actual compute.

The core reuses Study I's unchanged model and finite search. Local training
constructs one fresh-state row per target and excludes right padding from
target selection. Local prediction passes only the last two primitive tokens
to the original model's probability method. No adapter class, model wrapper,
compatibility layer, or new agent abstraction is introduced.

In the original PyTorch environment:

```bash
python -m unittest experiments.study_j.test_local -v
```

Hand-built fixtures check history invariance, matching short prefixes,
individual-context loss/gradients, padded physical input positions, persistent
updates, empty-corpus behavior, exhaustive independent local-prior ordering,
and 101 execution-budget boundaries. No development or formal environment
is generated by these checks.

The collector now journals both optimizers, shared initial tensors, six final
arms, four probes, physical training inputs, and actual recurrent ranking
positions. It requires the complete 33-environment task freeze before either
mode and PyTorch 2.8.0+cu126; formal collection also requires a matching
development audit's runtime, source, and data. These checks own the externally
supplied run/archive boundary and abort before collection on mismatch.

```bash
python -m unittest experiments.study_j.test_collection -v
```

Synthetic collection tests retain false accepted experience, demonstrate that
hidden data cannot change learning/search, preserve completed work and original
errors, reject incomplete/incompatible data and runtime changes, and compare
recorded physical input costs with actual forward calls.

The auditor independently regenerates initial tensors, replays both optimizers,
reconstructs local/full probabilities with NumPy GRU equations, and recomputes
search outcomes from complete functions. Physical training/ranking inputs and
all cost maps must match the exact phase ledger. It rejects incomplete grids
before inference and returns the pinned runtime for the formal collection gate.
